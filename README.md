# 飞花音 · 交互 Demo

> 以歌为令，以字会友 —— 实时多人在线的音乐飞花令
> TME Build With AI 高校 Hackathon · 方向一 · 落地：全民K歌

## 打开方式
双击 `index.html` 即可（纯前端、零依赖、离线可跑）。
建议用 Chrome / Edge 打开；窗口越接近手机比例，观感越好。
**声音（真实录音 + 真实音乐）**：
- **玩家自己的声音是真录的**：按住录音会用 `getUserMedia + MediaRecorder` 录下你的麦克风，松手后语音条里存的就是**你自己的原声**，点 ▶ 直接回放你本人刚唱的那一句（播放条标注「我的录音 · 这是你自己刚录下的原声」），不再用 AI 念字幕。录音时按钮上的波形是麦克风实时电平。
- **「一起听」播真实原唱片段**：官方音乐库 30 秒试听，直连 CDN，共收录 25 首（月/雨/风/夜/花等关键字下的主流曲目基本覆盖）。
- **兜底**：NPC 的语音条、或没有版权片段的曲目，会自动用「合成试听」（语音合成 + Web Audio 国风旋律），播放条上明确标注是「我的录音 / 原唱片段 / 合成试听」。
- 首次按住录音时浏览器会询问麦克风权限；拒绝也不影响流程，会自动落到合成试听。需要联网才能播原唱片段，离线时自动全量回退。
- 可在「我的 → 设置」里开关接歌语音播放。

**为什么不是完整 TME / QQ 音乐曲库**：完整曲库需要 TME / QQ 音乐开放平台的授权 appkey（商务合作 + 服务端签名），本地 HTML 演示文件里无法安全持有密钥；同时也不能把受版权保护的音频打包进 demo。拿到 appkey 后，只要替换 `app.js` 里的 `MUSIC` / `playReal()` 这一层即可全曲播放。

## 本次修改（按反馈）
1. **接歌时长可调**：默认从 8 秒放宽到 **30 秒**，可在「我的 → 设置 → 接歌时长」切换 8 / 15 / 20 / 30 秒（人机练习同步生效）。**NPC 接歌前会随机思考 3–5 秒**，节拍更像真人对局。
2. **玩家听到的是自己的真实录音**：按住录音会真的录麦克风，松手后语音条回放你本人的原声，而不是 AI 念识别结果。
3. **快速开局 = 点击即开局**：新手 / 欢乐 / 硬核 三档预设卡片，点一下直接进匹配→发牌→开唱，不用再选类型与玩法。
2. **技能卡页**去掉了右上角「打出来，不是抽出来」；技能卡整体移入「我的」。
5. **倒计时不再卡住**：每回合 8 秒到点或提交后立即进入「本回合结束 · 已提交，倒计时已归零重置」的结算态；下一回合重新从 8 开始计数（人机练习同样每回合自动重置）。同时加了回合锁，回合内只能提交一次，不会重复推进。
6. **接歌语音条可试听**：每条语音卡都有 ▶ 播放按钮 + 波形 + 时长，点开能听到念出的歌词；NPC 接歌、AI 裁判回复、AI 识别结果都会出声；「一起听」会播一段合成的原唱副歌旋律。
7. **接入真实歌曲片段**：「一起听」与语音条优先播放官方音乐库的真实原唱 30s 片段（25 首已收录并逐首验证可播），无片段时自动合成试听；新增底部播放条（封面/歌名/进度/暂停/关闭）与「原唱片段 / 合成试听」标识。
8. **底部导航「技能卡」→「我的」**：我的页展示段位称号（初入乐林→诗仙）、接歌数/胜局/最长连对/留档等数据，以及技能卡、共享歌单、战绩、留档、称号进阶入口与声音开关；首页多余的「技能卡」快捷入口已移除，避免功能重复。

## 部署到线上（在线链接）

本项目是纯静态站点，**可以直接部署到 GitHub Pages**，完整步骤见 [`DEPLOY.md`](./DEPLOY.md)。
简版：建一个空仓库 → `git remote add origin <你的仓库>` → `git push -u origin main` → Settings → Pages → 选 `main / (root)` → 访问 `https://<用户名>.github.io/<仓库名>/`。

## 文件结构
```
index.html      入口
styles.css      中式水墨视觉系统
data.js         曲库/歌词判定库、玩家、人设、技能卡等数据
app.js          交互逻辑与全部视图
assets/         水墨背景板（月/雨/风/夜）
preview/        各界面截图
```

> 演示数据均为模拟：曲库校验、识歌名、录音识别以「模拟数据 + 完整交互闭环」呈现（语音为浏览器 TTS 合成），真实接入为 ASR + LLM 语义校验 + TME 曲库 API + 文生图（见文档 15 章技术路径）。
